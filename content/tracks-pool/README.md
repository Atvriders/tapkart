## Why these were not swapped into v1

The shipped six were briefed as a deliberate progression — harbor-run easiest,
neon-district technical, caldera hardest, dust-canyon the dirt track,
redwood-rise the elevation track, glacier-pass fast-and-wide. They all pass.

Swapping on a measured proxy would be over-fitting: "worst off-track ticks"
measures how much margin a track leaves, not whether it is *fun*, and the design
spec is explicit that fun is human judgement. `quarry-run`'s 7 ticks is a
genuinely striking number — bots barely leave the road — but a track nobody
ever runs wide on may simply be too easy, and only a human can say.

What the pool is for: when a v1 track is played and found wanting, there are
twelve pre-validated replacements rather than a generation round.

Generated by `../pipeline/` with `tracks-pool.jsonl` as input; the instruction
file is byte-identical to the one that produced the v1 six, which is why this
run hit a 91.6% prompt-cache rate.
